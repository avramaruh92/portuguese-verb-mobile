<objective>
Wire the app layer to the now-async quiz-start flow: call Phase 7's `prefetch()` once at
root-layout mount so dataset resolution starts as early as possible, and make both call
sites (`app/index.tsx`'s Start, `app/results.tsx`'s Try Again) await the async
`startQuiz` before reading status — fixing the current "call then synchronously read
`.getState().status`" race. Each button gets a local loading flag so it is inert and gives
feedback during the await (state-machine behavior only; Phase 10 owns final visuals).

Purpose: The Start/Try Again flows must correctly await the async start (no stale-status
race), never hang or drop a tap silently, and kick the fetch off before the user finishes
picking tenses so the await resolves near-instantly on warm start.
Output: Updated `_layout.tsx`, `index.tsx`, `results.tsx`.
</objective>
