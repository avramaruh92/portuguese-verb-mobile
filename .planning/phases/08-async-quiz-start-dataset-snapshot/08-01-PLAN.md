<objective>
Make `useQuizStore.startQuiz()` async: await Phase 7's `resolveVerbs()`, snapshot the
returned `verbs` array, and pass that snapshot into `generate()` so the session is built
from whichever dataset (remote-fetched or local-fallback) is active at start time. Once
the session is built, its questions are frozen — a later background resolution returning
different verbs can never alter an in-progress quiz. This is the core of FETCH-04.

Purpose: A quiz must always be playable regardless of backend reachability, and an
in-progress session's questions must be immune to background dataset refreshes.
Output: An async `startQuiz` and updated/expanded store tests proving snapshot isolation.
</objective>
