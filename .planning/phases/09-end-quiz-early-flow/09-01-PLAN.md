<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| navigation → screen removal | Any back navigation (swipe, hardware back, programmatic) leaving the Quiz screen crosses here and could discard state without confirmation |
| in-progress session → next session | Store state persists across screen unmount (Zustand is module-global); stale session data can leak into the next quiz if not fully reset |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Information Disclosure | Early-exit path in app/quiz.tsx | mitigate | Confirmed exit calls `reset()` (clears session/answers/score) BEFORE navigating; no partial-results screen is rendered — REQUIREMENTS.md/Out-of-Scope forbids partial results |
| T-09-02 | Tampering (navigation integrity) | beforeRemove listener in app/quiz.tsx | mitigate | `beforeRemove` intercepts ALL removal paths (swipe/hardware/programmatic) per Pitfall 8; `gestureEnabled:false` alone is rejected as unreliable. On confirm, `reset()` guarantees the store returns to `initialState`, preventing stale-session corruption of the next `startQuiz()` (Pitfall 7, verified by Task 2 test) |
| T-09-03 | Denial of Service (double-dialog UX) | Exit-control availability | mitigate | Both header-button onPress and beforeRemove handler gate strictly on `status === "in-progress"`, so no confirmation fires after the quiz auto-completes on the last question (Pitfall 7 edge case) |
| T-09-SC | Tampering | npm/pip/cargo installs | accept | No new dependencies added this phase — D-02 uses RN core `Alert.alert`, D-01 uses expo-router's already-installed `Stack`/`useNavigation`. No install tasks, no package legitimacy gate required |
