<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → developer machine / CI | New third-party package (`linkedom`) executes install scripts and runs with full local filesystem access at build time |
| `assets/brand/*.svg` on disk → generator script | Local, version-controlled, developer-authored file; not attacker-controlled, but a malformed/unexpected shape silently producing wrong output is the real failure mode |

No network calls, no user input, no auth, and no runtime app code paths are touched by this plan.
The generated PNGs ship inside the app bundle, so the meaningful risk is supply-chain and
silent-corruption, not classic web attack categories.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-SC | Tampering | `npm install linkedom` | mitigate | Blocking human legitimacy checkpoint (Task 1) verifies publisher/repo/download-history on npmjs.com before install; `[ASSUMED]` fallback policy applied because no phase-level Package Legitimacy Audit exists. Not auto-approvable. |
| T-31-01 | Tampering | `assets/brand/lafa-icon.svg` promotion | mitigate | Path `d` data is copied byte-for-byte from the candidate and asserted byte-identical in acceptance criteria, so a silently-mangled mark cannot pass |
| T-31-02 | Elevation of Privilege | `linkedom` placement in `package.json` | mitigate | Asserted `devDependencies`-only and explicitly asserted absent from `dependencies`, so it cannot reach the shipped RN bundle |
| T-31-03 | Information Disclosure | promoted SVG contents | accept | The mark is public brand artwork; the dropped `<title>`/`<desc>` contain no sensitive data |
| T-31-04 | Denial of Service | build-time SVG parsing | accept | Input is a 12-line, version-controlled, developer-authored local file — no untrusted or unbounded input reaches the parser |
</threat_model>
