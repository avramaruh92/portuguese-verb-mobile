<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bundled asset → app render | `assets/images/lafa-homepage-lockup.png` is resolved statically by Metro at bundle time from a repo-controlled path. No network, no user input, no dynamic path construction crosses this boundary. |

This phase's attack surface is minimal and stated explicitly: a static, locally-bundled image rendered
by a React Native `Image`. There is no user input, no network request, no authentication, no
persistence, and no new dependency in this plan.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-06 | Tampering | `require()` asset path in `app/index.tsx` | mitigate | The path is a static string literal resolved by Metro at bundle time — no runtime/dynamic path construction, so no injected path can be substituted. A wrong path is a build-time bundler failure, caught by `npm run typecheck`/the simulator run in Task 2. |
| T-32-07 | Repudiation | Accessibility semantics lost in the Text→Image swap | mitigate | Explicit `accessibilityRole="image"` and the exact `accessibilityLabel` string are asserted by grep in Task 1's acceptance criteria and verified with VoiceOver in Task 2 check 8. |
| T-32-08 | Denial of service | `Image` layout collapse (0-height) hiding the screen's brand and shifting content | mitigate | `aspectRatio: 1600 / 520` plus `width: "100%"` guarantees a computed height; asserted by grep and confirmed visually in Task 2. |
| T-32-09 | Information disclosure | Rendered image contents | accept | Public brand artwork only — no secrets, PII, or environment data. |
| T-32-SC | Tampering | npm installs | accept | This plan installs no packages; `Image` is a core `react-native` primitive already in the bundle. No new supply-chain surface, so no install checkpoint is required. |
</threat_model>
