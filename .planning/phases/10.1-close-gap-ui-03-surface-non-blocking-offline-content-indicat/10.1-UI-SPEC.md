# Phase 10.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Platform note:** Expo/React Native (iOS-first) app — no shadcn, no Tailwind, no web component registry. All styling is native `StyleSheet.create` using the shared tokens module `src/theme/tokens.ts` shipped in Phase 10. This phase adds exactly one new visual element (a small informational pill) and introduces **zero new design tokens** — it reuses Phase 10's `colors.secondary` / `colors.textSecondary` / `typography.caption` / `radius.control` / `spacing.sm` verbatim, per 10.1-CONTEXT.md D-02.

## Spacing Scale

No new spacing tokens. Reuses Phase 10's `src/theme/tokens.ts` `spacing` export exactly as-is:

| Token | Value | Usage (this phase) |
|-------|-------|---------------------|
| sm | 8px | Pill internal padding — `paddingHorizontal: spacing.sm`, `paddingVertical: spacing.sm / 2` (4px, derived — do not add a new named token for this; it's half of an existing one, consistent with how the app already computes minor offsets) |
| md | 16px | Vertical gap between the pill and the content immediately below it on each of the 3 screens (matches existing screen horizontal-padding token, reused for consistency) |

Exceptions: none. Do not introduce any spacing value outside Phase 10's declared scale (8/12/16/24/48/64) for this phase's pill.

---

## Typography

No new typography tokens. Reuses Phase 10's `typography.caption` (14px / weight 400 / RN default line-height) for the pill's single line of text — this is the smallest existing role in the app and correctly signals low visual weight for a passive, non-blocking indicator.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Pill text (= existing Caption/Label role) | 14px | 400 (regular) | RN default (~1.2) |

Do not use `typography.body` (16px) or any semibold weight for this element — it must read as quieter than the surrounding screen content, not competing with headings or CTAs.

---

## Color

No new colors. Reuses exactly 2 of Phase 10's 7 declared values:

| Role | Value | Usage (this phase) |
|------|-------|---------------------|
| Pill background | `colors.secondary` (`#F2F2F7`) | Same "unselected/neutral surface" color already used for chips and choice tiles — signals informational, not alert-level |
| Pill text | `colors.textSecondary` (`#8E8E93`) | Same muted-gray role already used for the Results score caption — signals passive/secondary information |

Explicitly forbidden for this element: `colors.accent` (`#007AFF`) and `colors.error` (`#FF3B30`). Per 10.1-CONTEXT.md D-02, the pill must be visually distinct from both primary-action styling and error/destructive styling — it is neither a call-to-action nor a warning.

## Component Contract: "Using Saved Content" Pill

Since this phase introduces one new small visual element not covered by the generic template categories, its full contract is captured here.

| Concern | Contract |
|---------|----------|
| Trigger condition | Render only when the resolved dataset `source === "local"` (i.e. `resolveVerbs()`/`prefetch()` fell back from a failed/unreachable/invalid remote fetch — see `src/dataset/source.ts`). Never render when `source === "remote"` or before resolution completes. |
| Persistence (D-01) | Session-wide once triggered: once `source: "local"` is observed for the session, show the pill on **all 3 screens** (Setup, Quiz, Results) for the rest of the app session — not just on the screen/quiz that triggered it. |
| Shape/style (D-02) | Small neutral pill/badge — `backgroundColor: colors.secondary`, `color: colors.textSecondary`, `borderRadius: radius.control` (12px, reused from Phase 10), `paddingHorizontal: spacing.sm`, `paddingVertical: spacing.sm / 2`. NOT a full-width banner — width sizes to its text content (`alignSelf: 'flex-start'` or centered per-screen, not `width: '100%'`). |
| Copy (D-03) | "Using saved content" — text-only, no icon required. If an icon is added later (optional, Claude's discretion, not required this phase), it must not change the pill's neutral/secondary color treatment. |
| Placement — Setup (`app/index.tsx`) | Top of the screen body, below the native header, above the "Portuguese Verb Quiz" heading text. Use `spacing.md` (16px) margin-bottom before the heading. |
| Placement — Quiz (`app/quiz.tsx`) | Below the native header (which retains its existing Exit `headerLeft` control, unchanged from Phase 9/10), above the question content block. Use `spacing.md` margin-bottom. Do not place inside the header itself — headers in this app are titleless per Phase 10's contract, and the header's `headerLeft` slot is reserved for Exit. |
| Placement — Results (`app/results.tsx`) | Top of the screen body, above the score block. Use `spacing.md` margin-bottom before the score number. |
| Touch target | Not interactive — the pill is purely informational, no `Pressable`/`onPress`, no minimum 44px touch-target requirement applies (it is text, not a control). |
| Integration note (non-binding, implementation detail for planner/executor) | `src/dataset/source.ts`'s `resolveVerbs()`/`prefetch()` already computes `source` via the existing `cachedResult` memoization — do not call `resolveVerbs()` a second time or duplicate fetch/fallback logic to obtain this value. The natural integration point is either (a) capturing `source` alongside `verbs` in `useQuizStore.startQuiz()` (which already awaits `resolveVerbs()` and discards `source` today), or (b) a lightweight module-level read of the already-resolved `cachedResult` in `src/dataset/source.ts` consumed directly by screens outside a quiz-store field. Either satisfies this visual contract; the choice is architectural and left to planning/execution per 10.1-CONTEXT.md's Claude's Discretion section — this UI-SPEC only fixes the pill's trigger condition, visual treatment, placement, and copy. |
