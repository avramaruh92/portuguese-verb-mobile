## Decisions Made
- Testing required a Release-configuration build (embedded JS bundle) rather than the Debug dev-client, since the dev-client requires a live Metro connection at launch — Airplane Mode would otherwise block JS bundle loading itself rather than isolating the test to the app's own remote-verb-fetch fallback behavior.

## Deviations from Plan

None - plan executed exactly as written (on-device verification, no code changes).

## Issues Encountered
- iOS Simulator's Airplane Mode toggle does not cut network for the simulator process (it shares the host Mac's network stack), so verification was moved to a physical iPhone per user preference.
- Getting a build onto the physical device required: accepting an updated Apple Developer Program License Agreement, granting Keychain access for the "Apple Development" signing key (macOS login password), and building with `--configuration Release` (Debug dev-client requires live Metro over Wi-Fi, which Airplane Mode would have blocked). All resolved; verification then passed cleanly.
