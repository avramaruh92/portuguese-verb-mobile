# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope Note

Phase 1 is infrastructure-only (see `.planning/phases/01-scaffold/01-CONTEXT.md`, D-04). It creates a
single empty root route (`app/index.tsx`) proving Expo Router boots cleanly on the iOS simulator. There
is **no domain UI, no navigation between screens, no quiz/setup/results content, and no reusable
component library** in this phase — those belong to Phase 4+ (`UI hint: yes` phases per ROADMAP.md).

This contract is deliberately minimal: it covers only what is needed to render one placeholder screen
without visual ambiguity, and it establishes baseline tokens future phases will inherit rather than
redefine from scratch. Do not read this as a full app design system — Phase 4's UI-SPEC will expand it
with real screens, components, and copy for the quiz experience.

## Spacing Scale

Declared values (must be multiples of 4), per project convention for the whole app going forward:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: none. Phase 1's placeholder screen only needs a single centered container — no dense layout
decisions apply yet.

## Typography

Phase 1 renders exactly one line of placeholder text (e.g. app name or "Portuguese Verb Quiz"), no
information hierarchy is needed yet. Baseline roles declared now so Phase 4 inherits consistent values
rather than picking fresh ones:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | regular (400) | 1.5 |
| Label | 14px | regular (400) | 1.5 |
| Heading | 20px | semibold (600) | 1.2 |
| Display | 28px | semibold (600) | 1.2 |

Only 2 weights declared (400 regular, 600 semibold) per contract rule. Phase 1 itself only needs
`Heading` (20px/600) for the single placeholder line — Body/Label/Display are pre-declared for Phase 4+
reuse, not used this phase.

## Color

Phase 1 has no branded palette decision to make — this is a placeholder screen, not the product's visual
identity. Declaring safe, neutral system defaults now so Phase 1 doesn't block on a color decision that
belongs to Phase 4 (where real screens, cards, and interactive states exist).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (system white / default RN background) | Screen background |
| Secondary (30%) | `#F2F2F7` (iOS system gray 6) | Not used this phase — reserved for future card/surface use |
| Accent (10%) | `#007AFF` (iOS system blue) | Not used this phase — reserved for future primary CTA/interactive elements (Phase 4+) |
| Destructive | `#FF3B30` (iOS system red) | Not used this phase — reserved for future destructive actions (none exist in Phase 1) |

Accent reserved for: nothing in Phase 1 (no interactive elements exist on the placeholder screen).
Declared as a placeholder token only so Phase 4 does not need to invent it from scratch.

Text color: `#000000` (system black) at default RN opacity, on the `#FFFFFF` background above.
