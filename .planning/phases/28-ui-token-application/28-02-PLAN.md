<!-- The pressed-state mechanism is the ONLY new pattern in this phase and has -->
<!-- no in-repo precedent. UI-SPEC.md §"Interaction States" is authoritative.  -->

Mechanism (apply verbatim, D-04): convert an existing `style={[...]}` array
literal on a `Pressable` into `style={({ pressed }) => [...]}` returning the
same array shape, with `pressed && { backgroundColor: colors.pressed }`
appended as the LAST entry so it wins over the base background. Existing
conditional entries (e.g. disabled/hidden variants) stay in the array in their
current order. Never use `onPressIn`/`onPressOut`/`useState` press tracking.

Token available from src/theme/tokens.ts (already exists, no change needed by
this plan): `colors.pressed === "#C94A2D"`. `colors` is already imported by
name in all three screen files.

Relevant existing state in app/quiz.tsx: `lockedChoice` (string | null from
`useQuizStore`) and the local `choiceStyle(choice, correctAnswer)` helper which
returns `{ container, text }` style objects — `styles.choiceDefault` pre-lock,
`styles.choiceCorrect`/`styles.choiceWrong` post-lock.
</interfaces>
