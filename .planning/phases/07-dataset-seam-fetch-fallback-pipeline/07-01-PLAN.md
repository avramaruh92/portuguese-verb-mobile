## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering (data integrity) | src/dataset/remote.ts — fetched payload | mitigate | Validate `payload.verbs` with the existing `validateDataset()` (Zod `VerbSchema`) before accepting; reject on failure. Guard `Array.isArray(payload.verbs)` before validating so a non-array envelope also rejects (per research Pitfall 3). Never accept on `as Verb[]` type-assertion trust alone. |
| T-07-02 | Denial of Service (client-side) | src/dataset/remote.ts — fetch hang | mitigate | Bound the request with `AbortController` + `setTimeout(90_000)` (D-04). Fallback is silent (source.ts), and per D-03 the fetch is prefetch/non-blocking so even a full 90s hang never blocks the UI path. |
| T-07-03 | Tampering (silent-failure masking) | src/dataset/source.ts — fallback policy | accept | All failure modes fall through to the local bundled dataset with zero user-facing error (FETCH-03 requirement, by design). Accepted: a persistent backend outage silently serves stale bundled content — no user data at risk, and this is the explicit requirement. |
| T-07-SC | Tampering (supply chain) | npm installs | accept | No package installs this phase — reuses only already-installed deps (`zod`, native `fetch`, `AbortController`). Package Legitimacy Gate not applicable (no install task). |
