## Spacing Scale

Declared values — this project's existing scale (`src/theme/tokens.ts`), not the generic 8-pt default. Use these tokens by name; do not invent new spacing constants for this phase.

| Token | Value | Usage |
|-------|-------|-------|
| `spacing.sm` | 8px | Compact gaps (chip rows, label-to-content gaps) |
| `spacing.choiceGap` | 12px | Gap between stacked options in a list (pill/reason list) |
| `spacing.md` | 16px | Default element spacing, horizontal screen padding, gap between side-by-side buttons |
| `spacing.lg` | 24px | Section padding, vertical rhythm between blocks |
| `spacing.xl2` | 48px | Major section breaks (Results score block) |
| `spacing.xl3` | 64px | Page-level spacing (unused by this phase) |

Exceptions for this phase:
- Footer link (`ProductFeedbackLink` on Setup/Results) uses `marginTop: spacing.md` (16px) below the button/action group it follows — enough separation to read as secondary, not enough to feel orphaned.
- All new tappable targets (footer link, side-by-side quiz buttons, modal pills, submit button) keep the existing `minHeight: 44` convention used everywhere else in the codebase (iOS minimum touch target), even where visual height is smaller.

|------|------|--------|-------------|

No new type roles are introduced. The footer link deliberately uses `typography.caption` (the smallest declared size in the existing scale) to satisfy D-01/D-02's "small, low-visual-weight" requirement — do not bump it to `body` size.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `colors.background` `#FFFFFF` | Screen backgrounds, modal container |
| Secondary (30%) | `colors.surface` `#F2F2F1` | Pill/chip backgrounds (unselected), text input background |
| Accent (10%) | `colors.primary` `#E8663D` | Reserved for: selected category pill fill, Submit-feedback button fill, footer link text color, "Report a problem"/"Help us improve" trigger button text (Quiz screen, mirrors existing report-button treatment) |
| Success | `colors.success` `#2FA84F` | Submission success text only (`✓ ... sent — thank you!`) |
| Destructive/error | `colors.error` `#D64545` | Submission error text and Retry-submission button fill only — this phase has no destructive *actions* (nothing to confirm/undo), only an error *state* |

Accent reserved for (explicit list, nothing else may use `colors.primary` fill/text in this phase's new UI):
1. `ProductFeedbackLink` footer text on Setup and Results (text color only, no fill — this is what keeps it low-weight despite being accent-colored)
2. Selected state of the category pill (bug/idea/other) in `ProductFeedbackModal`
3. "Submit feedback" button fill in `ProductFeedbackModal`
4. "Report a problem" and "Help us improve" trigger-button text color on the Quiz screen (both mirror the existing `reportButtonText` treatment — text-only, no fill, matching current Quiz-screen convention)

## Component Inventory

New components/files this phase introduces, with their concrete visual contract (extends the sections above, mirrors `ReportFeedbackModal.tsx` structure per D-07):

### `ProductFeedbackLink` (or equivalent small footer component, rendered on Setup and Results)
- A single `Pressable` wrapping a `Text`, no background, no border, no icon.
- Text style: `typography.caption` + `color: colors.primary`, centered (`textAlign: "center"`).
- Container: `minHeight: 44` for touch target compliance, `justifyContent: "center"`, `alignItems: "center"`, `marginTop: spacing.md`.
- Placement: below the primary action group on each screen — below `startButton` on Setup (D-01), below the `actions` block (Share Score/Try Again/Back to Setup) on Results (D-02). Not a 4th equal-weight button; not a header icon.

### Quiz screen two-button row (`app/quiz.tsx` modification)
- Replace the current single, full-width `reportButton` with a `flexDirection: "row"` container, `gap: spacing.md`, two `flex: 1` (half-width) `Pressable`s.
- Both buttons reuse the exact existing `reportButton`/`reportButtonText` style (no fill, `colors.primary` text, `typography.body`, `minHeight: 44`) — equal visual weight per D-03, neither is upgraded to a filled/primary treatment.
- Divergent visibility per D-04 (not `opacity: 0`-hidden together as one row):
  - "Help us improve" button: visible and interactive from question-load (no `lockedChoice` gate).
  - "Report a problem" button: keeps existing `lockedChoice === null` → `opacity: 0` + `pointerEvents: "none"` gating, unchanged.
  - Because the two buttons have independent visibility, lay them out in a row container that is always rendered (not conditionally mounted), so the row doesn't jump/reflow when "Report a problem" fades in — the row's width is stable, only "Report a problem"'s opacity/pointer-events change.

### `ProductFeedbackModal.tsx` (`src/productFeedback/`)
Structural/visual mirror of `ReportFeedbackModal.tsx` (D-07), same `Modal` props (`presentationStyle="pageSheet"`, `animationType="slide"`), same `container`/`title`/pill-list/`textInput`/success-error text/submit-button/retry-button styles and tokens, with these field differences:
- Pill list renders 3 category pills (Bug/Idea/Other) instead of 4 reason pills — same `reasonOption`-equivalent styling (`minHeight: 44`, `paddingHorizontal: spacing.md`, `borderRadius: radius.control`, `backgroundColor: colors.surface` unselected / `colors.primary` selected, `typography.body` text `colors.text` unselected / `colors.background` selected).
- Message `TextInput` is **required** (unlike `ReportFeedbackModal`'s optional free text) — Submit button is `disabled` until `message.trim().length > 0`, using the existing `submitButtonDisabled` opacity-0.6 treatment for the disabled state (same visual language as Setup's `startButtonDisabled`). No live character counter (D-06) — the 2000-char ceiling is enforced only at submit time via schema/backend validation, surfaced through the same generic error text on a 400.
- No `verb`/`tense`/`subject`/`correctAnswer`/`selectedAnswer` props — only `screen`, `appVersion`, `platform` (PFDBK-05: zero quiz-answer fields ever constructed or displayed).
