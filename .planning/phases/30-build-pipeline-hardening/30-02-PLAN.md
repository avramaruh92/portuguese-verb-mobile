`eas build --profile production --platform ios`, read the exact Node version the
build image actually used out of the build log, and reconcile all three pinned
locations to that value if it differs from the locally-resolved guess.

`eas.json` `build.production.node`, plus a successful production build.

infrastructure and cannot be simulated locally.

  <name>Task 2: Reconcile the pin against the build-log-reported Node version</name>
  <files>.nvmrc, package.json, eas.json, package-lock.json</files>
  <action>

value currently in `.nvmrc`.

**Case B — mismatch (even a single patch digit, e.g. local 22.23.2 vs build image
22.23.1):** per RESEARCH.md Pitfall 1, correct the pin to the build-log value —
the build log is authoritative, the local nvm resolution is not. Do NOT accept the

  1. Update all three locations to the exact build-log-reported string:
     `.nvmrc` (bare, no `v` prefix), `package.json` `engines.node`, and

     `export NVM_DIR="$HOME/.nvm" && source "$NVM_DIR/nvm.sh" && nvm install <version> && nvm use`

     `rm -rf node_modules package-lock.json && npm install`

  the two patches ship the same bundled npm), note that — it means only the
  declared version strings changed, and Task 3's confirming rebuild is a
