### `package.json` (config, batch)

**Analog:** itself (current committed state, in-place edit target)

**Current devDependencies pinning convention** (`package.json:32-39`):
```json
"devDependencies": {
  "@types/jest": "29.5.14",
  "@types/react": "~19.2.2",
  "eslint": "^9.0.0",
  "eslint-config-expo": "~57.0.0",
  "jest-expo": "~57.0.2",
  "typescript": "~6.0.3"
}
```
Established convention: devDependencies use `~` (tilde, patch-flexible) for
Expo-SDK-paired tooling (`eslint-config-expo`, `jest-expo`, `typescript`) and `^`
(caret) for standalone tools not tied to the Expo SDK release cadence (`eslint`).
`eas-cli` is standalone/not SDK-paired, so per D-04 it follows the `^` convention:
```json
"eas-cli": "^21.0.3"
```

**Current dependencies pinning convention** (`package.json:5-31`):
```json
"expo": "~57.0.7",
"expo-constants": "~57.0.3",
"expo-linking": "~57.0.3",
"expo-router": "~57.0.7",
"expo-splash-screen": "~57.0.4",
"expo-web-browser": "~57.0.1",
"react-native-screens": "4.25.2",
```
Pattern to apply — `npx expo install --fix` bumps these in place to the
`expo-doctor`-reported target versions (tilde ranges preserved for the
`expo-*` packages; `react-native-screens` moves from an exact pin `4.25.2` to
tilde `~4.26.0`, matching how `expo install --fix` writes ranges — do not
hand-edit version strings, let the tool write them):
```json
"expo": "~57.0.8",
"expo-constants": "~57.0.7",
"expo-linking": "~57.0.4",
"expo-router": "~57.0.8",
"expo-splash-screen": "~57.0.5",
"expo-web-browser": "~57.0.2",
"react-native-screens": "~4.26.0",
```

**Scripts pattern** (`package.json:40-48`):
```json
"scripts": {
  "start": "expo start",
  "android": "expo start --android",
  "ios": "expo start --ios",
  "web": "expo start --web",
  "lint": "expo lint",
  "test": "jest",
  "typecheck": "tsc --noEmit"
}
```
Pattern to apply — one flat verb-named script per external tool invocation,
matching this existing style. Per RESEARCH.md Pitfall 1 (stale global `eas-cli`
shadowing), add an `eas` script so `npm run eas -- <subcommand>` always resolves
the pinned local `node_modules/.bin/eas`, not a global install:
```json
"eas": "eas"
```

## Shared Patterns

### Dependency version pinning convention
**Source:** `package.json:5-39` (both `dependencies` and `devDependencies` blocks)
**Apply to:** the new `eas-cli` devDependency entry and all 7 `expo install --fix`-bumped packages
- Expo-SDK-paired packages (`expo`, `expo-*`, `jest-expo`, `eslint-config-expo`,
  `typescript`, `react-native-screens`): tilde (`~`) ranges, patch-flexible only.
- Standalone tools not tied to Expo's SDK cadence (`eslint`, `zod`, `zustand`,
  `eas-cli`): caret (`^`) ranges.

### CLI invocation via npm script, not bare npx
**Source:** RESEARCH.md Pitfall 1 (`.planning/phases/20-native-build-risk-front-loading/20-RESEARCH.md` lines 273-287)
**Apply to:** every `eas` subcommand this phase (and future EAS-touching phases
20/23/24) runs
```bash
npm run eas -- build:configure
npm run eas -- build --platform ios --profile production --clear-cache
npm run eas -- build:list --platform ios --status finished --limit 1 --json
```
Guarantees the pinned local `eas-cli@^21.0.3` runs instead of a shadowing
global install (`eas-cli@20.0.0` confirmed present on this dev machine).

### Sequencing: dependency fixes before release-identity config
**Source:** RESEARCH.md Pattern 1 (`.planning/phases/20-native-build-risk-front-loading/20-RESEARCH.md` lines 211-224)
**Apply to:** the plan's task ordering across `package.json`/`package-lock.json`
(first) and `app.json`/`eas.json` (second)
```bash
npx expo-doctor              # baseline: 19/20 checks passed
npx expo install --fix       # applies the 7 patch/minor bumps
npx expo-doctor              # confirm: 20/20 checks passed
```
