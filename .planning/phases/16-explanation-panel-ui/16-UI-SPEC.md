## Spacing Scale

This project's declared scale (`src/theme/tokens.ts`'s `spacing` export — do
not introduce new values):

| Token | Value | Usage |
|-------|-------|-------|
| sm | 8px | Compact spacing (pill padding, label gaps) |
| md | 16px | Default element spacing — panel's internal padding |
| lg | 24px | Section padding — panel's `marginBottom`/`marginTop` |
| choiceGap | 12px | Gap between answer-choice buttons (existing token, unrelated to this phase) |
| xl2 | 48px | Major section breaks (unused this phase) |
| xl3 | 64px | Page-level spacing (unused this phase) |

Note: this project's scale is not the standard 4/8/16/24/32/48/64 template
— it has no `xl`(32px) token and uses `choiceGap`(12px) as a named
exception. Do not invent an `xl` value for this phase; reuse `md`/`lg` only.

**Panel spacing contract:**
| Property | Value |
|----------|-------|
| `paddingHorizontal` | `spacing.md` (16px) |
| `paddingVertical` | `spacing.md` (16px) |
| `marginTop` | `spacing.md` (16px) — gap from the choices block above |
| `marginBottom` | `spacing.lg` (24px) — matches the existing `marginBottom: spacing.lg` pattern used by `choices`/`questionBlock`/`progressRow` in `quiz.tsx`, so the Next button's spacing from whatever sits above it is unchanged whether the panel is present or not |

Exceptions: none.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (panel text) | 16px (`typography.body`) | 400 | default (no explicit `lineHeight` in `typography.body` — do not add one; RN's default line-height for 16px system font is acceptable here) |
| Label | not used — D-03 locks "sentence only, no heading/label" | — | — |
| Heading | not used in this component | — | — |
| Display | not used in this component | — | — |

**Rationale for using `typography.body` (16px) rather than
`typography.caption` (14px, the size `OfflinePill` uses):** D-01 locks the
*card treatment* (`colors.surface` bg + `colors.textSecondary` text) as
matching `OfflinePill`'s quiet pattern, but `OfflinePill` is a short
single-line pill label, while this panel renders a full 1-2 sentence
explanation. `typography.body` is the same size already used for the
question meta row (`metaRow` style in `quiz.tsx`) and choice text
(`choiceText`), so a full sentence at 16px stays legible and visually
consistent with the rest of the screen's body copy rather than reading as
fine print.

Text style: `{ ...typography.body, color: colors.textSecondary }`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `colors.background` (`#FFFFFF`) | Screen background |
| Secondary (30%) | `colors.surface` (`#F2F2F1`) | Cards, choice buttons, progress track, **explanation panel background** |
| Accent (10%) | `colors.primary` (`#E8663D`) | Progress fill, Next button, Exit/Report link text — NOT used anywhere in this panel |
| Destructive | `colors.error` (`#D64545`) | Wrong-choice highlight only — NOT the panel background/border (panel must stay visually distinct from the red wrong-answer highlight already shown on the choice button per D-01) |

Panel-specific color contract:
| Element | Token | Value |
|---------|-------|-------|
| Panel background | `colors.surface` | `#F2F2F1` |
| Panel text | `colors.textSecondary` | `#6B6560` |
| Panel border | none — no border, matches `OfflinePill`'s borderless fill card |

Accent reserved for: progress bar fill, Next button background, Exit
button text, Report a problem button text. The explanation panel uses
neither `colors.primary` nor `colors.error`/`colors.success` anywhere —
this is the explicit purpose of D-01 (read as supplementary info, not an
alert, and stay visually distinct from the correct/wrong choice
highlighting).

## Component Contract

**New component:** `src/components/ExplanationPanel.tsx`, following
`OfflinePill.tsx`'s existing shape (small, self-contained, imports tokens
directly, named export, no default export).

**Props:**
```ts
interface ExplanationPanelProps {
  text: string;
}
```
The component is a pure presentational card — `app/quiz.tsx` owns calling
`selectExplanation(...)` and passing the resolved string as `text`. The
component itself does not call `selectExplanation` and does not know about
`Verb`/`learning` types (keeps it a dumb, reusable render primitive,
consistent with `OfflinePill`'s self-contained-but-narrow scope).

**Render contract:**
```tsx
<View style={styles.container} testID="explanation-panel">
  <Text style={styles.text}>{text}</Text>
</View>
```

**Style block:**
```ts
const styles = StyleSheet.create({
  container: {
    backgroundColor: colors.surface,
    borderRadius: radius.control,
    paddingHorizontal: spacing.md,
    paddingVertical: spacing.md,
    marginTop: spacing.md,
    marginBottom: spacing.lg,
  },
  text: {
    ...typography.body,
    color: colors.textSecondary,
  },
});
```

**Placement in `app/quiz.tsx`:** between the `choices` `<View>` block and
the `nextButton` `<Pressable>` — i.e. immediately after the closing `</View>`
of `styles.choices` and before the `<Pressable onPress={handleAdvance} ...>`
block (satisfies EXPL-02's "placed between the answer choices and the Next
button" literally, matching the JSX render order, not just visual position).

**Mount condition (D-02, conditional mount, no reserved space):**
```tsx
{lockedChoice !== null && lockedChoice !== question.correctAnswer && explanation && (
  <ExplanationPanel text={explanation} />
)}
```
where `explanation` is computed each render (or via `useMemo` keyed on
`question`/`lockedChoice` — implementer's choice per CONTEXT.md discretion)
by calling `selectExplanation(currentVerb, lockedChoice, question.correctAnswer, learning)`
and is `undefined` when no match resolves. No `opacity: 0` /
`pointerEvents: "none"` reserved-space pattern (unlike `nextButtonHidden`/
`reportButtonHidden` in the same file) — the panel must not exist in the
tree at all when there is no explanation, per EXPL-03's literal
"no explanation panel is shown."

**Animation/timing (D-04):** none. No `Animated`, no `LayoutAnimation`, no
delay — the panel appears in the same render pass as the locked-choice
color change on the choice buttons.

**Accessibility:**
- `testID="explanation-panel"` on the container `View` (enables screen/e2e
  verification that EXPL-02/EXPL-03's presence/absence rules hold without
  relying on visual snapshot).
- No explicit `accessibilityRole`/`accessibilityLabel` override needed —
  the child `Text` node is auto-exposed to VoiceOver/TalkBack by default RN
  behavior; do not add `accessible={true}` grouping on the container, as
  that would suppress the natural text announcement.
- `numberOfLines`: unset (allow full wrap — copy is capped at "short
  (1-2 sentence)" per EXPL-02, so no truncation risk; do not add
  `ellipsizeMode`).
- No fixed `maxWidth` — panel spans the same content width as the choice
  buttons and question block above it (`ScrollView`'s `contentContainerStyle`
  already constrains horizontal padding via `spacing.md`), so text wraps
  naturally at the screen width minus existing screen padding.

**Wiring gaps this phase must also close** (per CONTEXT.md
`<decisions>` → Claude's Discretion, restated here as an explicit contract
requirement so the checker can verify it, not just the planner):
1. `useQuizStore`'s `startQuiz` must expose `learning` from
   `resolveVerbs()`'s `{ verbs, source, learning }` result to screens (it
   currently discards it).
2. `app/quiz.tsx`'s `currentVerb` lookup must read from the session's
   resolved/snapshotted verb list (which carries `formIndex`), not the
   locally bundled `src/dataset/verbs.ts` import — otherwise
   `selectExplanation` never receives a `Verb` with `formIndex` even on a
   successful remote fetch, and the panel silently never appears.
