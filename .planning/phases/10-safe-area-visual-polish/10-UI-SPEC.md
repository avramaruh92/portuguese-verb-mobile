# Phase 10 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Platform note:** This is an Expo/React Native (iOS-first) app, not a web/Next.js/Vite project. shadcn is not applicable — there is no `components.json`, no Tailwind, no web component registry. All styling is native `StyleSheet.create` objects per screen. The shadcn gate in the researcher instructions was evaluated and skipped for this reason (recorded below as `Tool: none`).

## Spacing Scale

Declared values (existing app-wide scale, source: `app/index.tsx`, `app/quiz.tsx`, `app/results.tsx` — confirmed in 10-CONTEXT.md D-03, standard-set members are multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | not currently used — reserved, no exception needed |
| sm | 8px | `sectionLabel`/`progressText` bottom margin, chip row gap |
| md | 16px | Screen horizontal padding (all 3 screens), default element spacing, action-stack gap on Results |
| lg | 24px | Section margin-bottom (Setup sections, Quiz content padding/question block/choices), error-text margin |
| 2xl | 48px | Results score-block bottom margin |
| 3xl | 64px | Results container top padding (legacy manual notch offset — see Safe-Area Contract below, this phase replaces this literal with a real inset) |

Exceptions:
- **12px (choice-list gap on Quiz, `choices.gap`, also shared with border-radius on buttons/chips/choice tiles) is NOT a member of the standard 8-point scale (4/8/16/24/32/48/64), and is retained unchanged as a documented exception, not tokenized away.** Justification: 10-CONTEXT.md D-03 explicitly locks this phase to "a **pure tokenization pass, not a redesign**... extract these exact values (plus the existing spacing scale: 8/12/16/24/48/64 and font sizes: 14/16/20/56) into a shared tokens module all 3 screens import from, with **zero visible color/spacing change to the end user**." Since 12px is one of the pre-existing, already-shipped values D-03 names verbatim and mandates preserving exactly, snapping it to 8px or 16px during this phase would violate that locked decision (it would be a visible spacing change, which D-03 forbids). This value must be centralized into the shared tokens module (e.g. `spacing.choiceGap = 12` and/or `radius.control = 12`) exactly as-is — do not introduce it as a new one-off value elsewhere, and do not use 12px for any new spacing decision this phase.
- Touch targets: all interactive elements (buttons, chips, choices) already use `minHeight: 44` — the iOS minimum tappable target. Preserve this exactly; do not shrink it when adding the loading-indicator glyph to the Start/Try Again buttons.

## Typography

Declared values (existing, source: same 3 screen files, confirmed in 10-CONTEXT.md D-03):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Caption/Label | 14px | 400 (regular) | RN default (~1.2); no explicit `lineHeight` set today — do not add one as part of this tokenization pass |
| Body | 16px | 400 (regular) for body text, 600 (semibold) for button/CTA text | RN default; body text is single-line/short, no multi-line paragraph exists in this app to warrant 1.5 |
| Heading | 20px | 600 (semibold) | RN default |
| Display | 56px | 600 (semibold) | 62px (explicit, existing — Results score number only) |

Only 4 sizes (14/16/20/56) and exactly 2 weights (400/600) exist in the app today — this satisfies the "3-4 sizes, 2 weights max" contract with zero new values introduced. Do not add a 5th size or a 3rd weight during this phase.

## Color

Declared values (existing iOS-system palette, locked unchanged per 10-CONTEXT.md D-03 — "pure tokenization pass, not a redesign"):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Screen background on all 3 screens |
| Secondary (30%) | `#F2F2F7` | Unselected chips, choice tiles (default state), progress track background, Back-to-Setup button background |
| Accent (10%) | `#007AFF` | Reserved for: Start Quiz button, Try Again button, Share Score button, selected tense chip background + its selected text color, progress-bar fill, Quiz header "Exit" text, "Report a problem" text, Back-to-Setup button label text |
| Destructive/Error | `#FF3B30` | Reserved for: wrong-answer choice highlight on Quiz, error-state text on Setup/Results (`status === 'error'` and unexpected-error fallback text) |
| Success (non-primary semantic) | `#34C759` | Correct-answer choice highlight on Quiz only — not a general "positive" color, scoped to this one use |
| Primary text | `#000000` | Headings, body copy, unselected choice/chip text |
| Secondary text | `#8E8E93` | Results score caption ("correct out of N questions") only |

Accent reserved for: primary action buttons (Start Quiz / Try Again / Share Score), the selected-state of tense chips, the progress-bar fill, and the two text-only link-style controls (Exit, Report a problem, Back to Setup label). Never apply accent blue to body text, section labels, or unselected chip/choice backgrounds.

No new colors are introduced this phase. All 7 values above must be centralized into one shared tokens module (see Implementation Notes) and imported by all 3 screens' `StyleSheet.create` calls — eliminating the current hex-literal duplication across `app/index.tsx`, `app/quiz.tsx`, `app/results.tsx`.

## Layout & Safe-Area Contract (phase-specific, supplements template)

This phase's core work is layout/chrome, not new visual style — captured here explicitly since the generic template categories above don't cover header/inset behavior.

| Concern | Contract |
|---------|----------|
| Root wrapping | `SafeAreaProvider` (from `react-native-safe-area-context`, already a dependency) wraps `<Stack>` in `app/_layout.tsx`. This is the only mount point — no per-screen providers. |
| Top safe area | Delivered via a native Expo Router header on **all 3 screens** (Setup, Quiz, Results), not manual inset math. `app/_layout.tsx`'s `screenOptions` flips from `headerShown: false` (current) to `headerShown: true` app-wide, or each screen sets it individually — either is acceptable as long as all 3 screens end up with a shown header. |
| Header title | Every header is titleless: `headerTitle: ""` on all 3 screens (Quiz already does this — replicate exactly on Setup and Results). On-screen "Portuguese Verb Quiz" heading text on Setup stays in the screen body, unchanged. No title text added to Results. |
| Header left/right | Quiz keeps its existing `headerLeft` Exit `Pressable` (Phase 9 behavior unchanged, restyle only if needed for token consistency). Setup and Results default to chrome-only headers with no `headerLeft`/`headerRight` — Results already has an in-body "Back to Setup" button, so a header back affordance would be redundant. Do not add one unless a specific layout problem is found during implementation. |
| Bottom safe area | Not covered by the native header — must be handled explicitly per-screen using `useSafeAreaInsets()` (preferred over `SafeAreaView` for finer control alongside `ScrollView`/`View` `paddingBottom`) on each screen's scrollable/actionable content, so the Start/Try Again/Share/Back buttons and Quiz's Next/Report buttons never sit under the iOS home-indicator gesture area. |
| Results' legacy `paddingTop: 64` | This literal was a manual, ad hoc notch workaround predating this phase. Once the native header is in place on Results, re-evaluate whether 64px top padding is still needed on top of the header's own inset — it likely should be reduced or removed to avoid doubled top spacing. Confirm visually during implementation; do not leave both a header AND the old 64px padding stacked without checking for excess whitespace. |
| Loading indicator scope | The ONLY loading-state UI in the app is the existing "Starting…" text swap on Setup's Start button and Results' Try Again button — augmented this phase with a native `ActivityIndicator`. No new always-visible loading element is added anywhere (confirmed 10-CONTEXT.md D-04; background `prefetch()` in `app/_layout.tsx` stays fully silent). |
| Error/fallback styling scope | Restyle only the existing `status === 'error' && errorMessage` and `unexpectedError` red-text blocks on Setup (`app/index.tsx`) and Results (`app/results.tsx`) using the shared tokens (proper spacing/optional card/container treatment instead of bare inline `Text`) — do not add a new error surface, toast, or banner component (confirmed 10-CONTEXT.md D-05). |
| Shared tokens module | Claude's discretion on exact path/shape (10-CONTEXT.md), but must be a single module (e.g. `src/theme/tokens.ts`) exporting the color/spacing/typography values declared in this contract, imported by all 3 screens' `StyleSheet.create` calls. Recommend a flat-object shape (`export const colors = {...}`, `export const spacing = {...}`) for straightforward `StyleSheet.create` interop — a class-based or styled-components-style theme is unnecessary overhead for 3 screens of plain RN styles. |
