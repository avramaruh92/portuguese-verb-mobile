<objective>
Deliver the user-facing report-a-problem slice: a modal component wired into the Quiz screen. A learner who has answered the current question can tap "Report a problem," pick a preset reason, optionally add free text, and submit — with inline spinner, success checkmark auto-dismiss, and generic error + conditional Retry handling. All of it runs in modal-local state, never touching `useQuizStore`, so the quiz underneath stays fully interactive during an in-flight (possibly cold-starting) request.

Purpose: FDBK-01 (user can submit feedback with question context) and FDBK-03 (submission never blocks/interrupts the quiz). This is the vertical slice that turns Plans 01+02's pure logic into a capability the learner can actually use.

Output: `src/feedback/ReportFeedbackModal.tsx` (new component) + modified `app/quiz.tsx` (trigger button + modal render). Visuals per approved 05-UI-SPEC.md.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Quiz screen ↔ feedback modal | Modal reads current-question context (read-only) from props sourced from the store; it must not write back. |
| Modal → external API | Submission crosses to `POST /feedback` (transport owned by Plan 02's submitFeedback). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02 | Information Disclosure | Error rendering in modal | mitigate | Modal shows only generic "Something went wrong. Please try again." on any failure; never renders response body / fields (D-06/D-07). No internals reach the UI. |
| T-05-04 | Tampering | Quiz session state via feedback flow | mitigate | Modal keeps all state in local `useState`; grep gate + `git diff` prove `useQuizStore` is never written this phase (FDBK-03 / RESEARCH Pitfall 3). |
| T-05-05 | Denial of Service | Cold-start request blocking quiz interaction | mitigate | Submission runs in modal-local async; the Quiz screen never awaits it. 90s bound comes from Plan 02. Dismissing mid-flight is an implicit cancel (D-04). Live non-interruption verified in Plan 04. |
| T-05-06 | Denial of Service | Trapped modal / stale timer | mitigate | `presentationStyle="pageSheet"` + `onDismiss` guarantees an iOS dismiss path with no cancel button; reset-on-open + `clearTimeout` on close/unmount prevent a stale auto-dismiss timer from firing `onClose` on a later question. |
| T-05-SC | Tampering | npm installs | accept | No new packages — RN core `Modal`/`TextInput`/`ActivityIndicator` + already-installed `expo-constants`. |
</threat_model>
