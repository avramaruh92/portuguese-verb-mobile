## Color

Existing palette in `src/theme/tokens.ts` (locked by Phase 26), plus one new token this phase adds:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFF9F6` (`colors.background`) | Screen backgrounds |
| Secondary (30%) | `#F1EFED` (`colors.surface`) | Cards, choice-button surfaces, dividers |
| Accent (10%) | `#F2643E` (`colors.primary`) / `#FDE7DF` (`colors.primarySoft`) | Primary CTA buttons, active/selected states, primary text accents |
| Pressed (new wiring this phase) | `#C94A2D` (`colors.pressed`) | Pressed-state background override on primary-action buttons only (see Interaction States below) — token already existed, unused until this phase |
| Info (new wiring this phase) | `#36799A` (`colors.info`) | `OfflinePill` text color only |
| Info Soft (**new token, added this phase**) | see below | `OfflinePill` background only |
| Destructive/Error | `#D64545` (`colors.error`) | Incorrect-answer state on quiz choice buttons (not a destructive-confirmation action — no delete/destroy flows exist in this app) |
| Success | `#1F7F66` (`colors.success`) | Correct-answer state on quiz choice buttons |

Accent (`colors.primary`/`colors.primarySoft`) reserved for: Setup screen's Start Quiz button (default state), Quiz screen's Next button (default state) and selected/unanswered choice buttons, Results screen's Share Score and Try Again buttons (default state), feedback modals' Submit/Retry buttons (default state). Never used for chips, links, or the header Exit control (those stay on `colors.text`/`colors.textSecondary`).

### New token: `colors.infoSoft`

- **Hex:** `#DCEBF0` (a light desaturated tint of `#36799A`, targeting roughly the same tint-depth/luminance relationship that `primarySoft` (`#FDE7DF`) has to `primary` (`#F2643E`) — both are pale, low-saturation backgrounds meant to sit under solid-colored text of the paired base token).
- **Placement:** insert directly after `info: "#36799A"` in the `colors` object literal in `src/theme/tokens.ts`, mirroring the existing adjacency of `primary` → `primarySoft`:
  ```ts
  export const colors = {
    primary: "#F2643E",
    primarySoft: "#FDE7DF",
    pressed: "#C94A2D",
    info: "#36799A",
    infoSoft: "#DCEBF0",
    success: "#1F7F66",
    error: "#D64545",
    background: "#FFF9F6",
    text: "#24201E",
    textSecondary: "#746D69",
    surface: "#F1EFED",
  };
  ```
- **Test update:** `src/theme/tokens.test.ts`'s `colors` `toEqual()` block (lines 5-16) must add `infoSoft: "#DCEBF0",` in the same position, or the exact-shape assertion will fail. Keep the existing single `toEqual()` block structure (no restructuring needed — this is a one-line addition within the already-exhaustive object comparison).

## Interaction States — Pressed State (new contract this phase)

This phase introduces the app's first use of `Pressable`'s function-form `style` prop. Apply this exact mechanism, verbatim, to every button listed below — no `onPressIn`/`onPressOut`/`useState` tracking anywhere:

```tsx
<Pressable
  style={({ pressed }) => [
    styles.someButton,
    pressed && { backgroundColor: colors.pressed },
    /* any existing conditional disabled/state styles stay in the array too */
  ]}
  ...
>
```

**In scope (gets pressed-state styling):**

| Screen/Component | Button(s) |
|---|---|
| `app/index.tsx` | `startButton` (Start Quiz) |
| `app/quiz.tsx` | Choice buttons — **only while `lockedChoice === null`** (unanswered). Once a choice is locked, `colors.success`/`colors.error` styling takes over and pressed-state must not apply — compose with, not replace, the existing correct/incorrect conditional-style array. |
| `app/quiz.tsx` | `nextButton` |
| `app/results.tsx` | `shareButton`, `tryAgainButton` |
| `src/feedback/ReportFeedbackModal.tsx` | Primary submit button, error-state retry button |
| `src/productFeedback/ProductFeedbackModal.tsx` | Primary submit button, error-state retry button |

**Explicitly out of scope (no pressed-state change — leave exactly as-is):**

- Setup screen tense/verb-mode selector chips
- Header Exit link (all screens)
- "Report a problem" / "Help us improve" text-link triggers
- Results screen's Back to Setup link

Do not add pressed-state styling to anything not in the in-scope table, even if it seems consistent to do so — this was explicitly scoped down in CONTEXT.md D-03 and confirmed in the discussion log's scope check.
