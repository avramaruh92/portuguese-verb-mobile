# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** This is an Expo React Native (iOS-first) app, not a web app. shadcn/Tailwind/Radix are web-only tools and do not apply — the shadcn initialization gate is not applicable here. All styling uses React Native's `StyleSheet.create` with plain View/Text/Pressable/Switch primitives, matching the existing pattern in `app/index.tsx` (the only precedent in the codebase). No component library or design token system exists yet; this phase establishes the first real UI patterns for the app.

## Spacing Scale

Declared values (must be multiples of 4), source: default GSD 8-point scale, no upstream override found:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/label gaps, inline padding within a chip or choice button |
| sm | 8px | Compact spacing between related elements (e.g. text counter + progress bar) |
| md | 16px | Default spacing between elements (tense chips, answer choices, screen horizontal padding) |
| lg | 24px | Section padding (setup screen groups, results screen sections) |
| xl | 32px | Layout gaps (space above/below the score display, above the answer-choice list) |
| 2xl | 48px | Major section breaks (space between score display and action buttons) |
| 3xl | 64px | Page-level spacing (top padding on results screen to visually center the score) |

Exceptions: Answer-choice buttons and toggle/switch touch targets must be minimum 44x44pt per iOS Human Interface Guidelines, even where that exceeds the nearest 8-pt spacing token — this applies to every tappable element in this phase (tense chips, irregular toggle, answer choices, Next/Try Again/Back to Setup/Share buttons).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | Regular (400) | 1.5 |
| Label | 14px | Regular (400) | 1.5 |
| Heading | 20px | Semibold (600) | 1.2 |
| Display | 56px | Semibold (600) | 1.1 |

Notes:
- 4 sizes / 2 weights declared, per contract limit.
- **Heading (20/600)** matches `app/index.tsx`'s existing style exactly — reused as-is for screen titles ("Setup", question counter area doesn't need a heading, "Results").
- **Display (56/600)** is reserved exclusively for the results screen's "X/10" score per D-09 ("large, prominent... visual centerpiece") — nothing else in this phase uses Display size.
- **Body (16/400)** is used for verb/translation/subject text on the quiz screen and answer-choice labels.
- **Label (14/400)** is used for the progress counter ("3 / 10"), tense/subject metadata, and helper copy (e.g. setup screen inline error text).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Screen background on all 3 screens — matches existing `app/index.tsx` |
| Secondary (30%) | `#F2F2F7` | Answer-choice button default background, tense-chip default background, card-like grouping surfaces (iOS system-gray-6 equivalent) |
| Accent (10%) | `#007AFF` | Primary interactive elements only: "Start Quiz" button, selected tense chip border/fill, "Next" button, "Try Again" button (iOS system blue) |
| Correct feedback | `#34C759` | Correct answer highlight (selected-and-correct OR reveal-of-correct-when-wrong) per D-05 |
| Destructive / incorrect feedback | `#FF3B30` | Wrong-answer highlight per D-05 (also reserved for any future destructive-confirmation copy, none exists in this phase) |

Accent (`#007AFF`) reserved for: "Start Quiz" button, selected/active tense chip, the irregular-verbs toggle's "on" track color (RN `Switch` default iOS behavior), "Next" button on the quiz screen, "Try Again" button on results, and the share-sheet trigger button. Never used for plain body text, backgrounds, or unselected/inactive elements.

Green (`#34C759`) and red (`#FF3B30`) are reserved exclusively for D-05's answer-feedback semantics (correct/wrong choice highlighting) — not used decoratively anywhere else in this phase.

Text color: `#000000` on light backgrounds (matches existing precedent), `#FFFFFF` on filled accent/feedback buttons for contrast.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (Setup) | "Start Quiz" — disabled (grayed, non-interactive) until ≥1 tense selected per D-02 |
| Primary CTA (Quiz, per-question) | "Next" — appears only after an answer is locked (D-06/D-07), never before |
| Primary CTA (Results) | "Try Again" — re-derives a fresh session with the same filters per D-11 |
| Secondary action (Results) | "Back to Setup" — returns to the setup screen to change filters (D-11) |
| Share action (Results) | "Share Score" (button label) → opens native iOS share sheet with message: `"I scored X/10 on Portuguese Verb Quiz!"` (D-10, exact text, substitute actual score for X) |
| Setup toggle label | "Include irregular verbs" — label text only, no helper copy underneath (D-03) |
| Setup "All tenses" shortcut | "All tenses" — toggles all 4 tense chips at once (D-01) |
| Error state (Setup, D-04) | "Not enough verbs for that combination — try selecting more tenses or including irregulars." Inline on the setup screen, below the tense/toggle controls, above the (disabled or hidden) Start Quiz button. User stays on the setup screen; never navigates away. |
| Progress indicator (Quiz) | Text counter: "{currentIndex+1} / 10" alongside a visual progress bar (D-08) — both shown together, not either/or |
| Score display (Results) | Large "X/10" as the visual centerpiece (D-09) — no surrounding sentence needed, the number itself is the primary copy |
| Destructive confirmation | None in this phase — no destructive actions exist (no delete/reset-with-data-loss action; "Back to Setup" and "Try Again" both discard the just-completed session but that's expected quiz-flow behavior, not a destructive action requiring confirmation) |

## Screen-by-Screen Interaction Contract

(Supplementing the standard template sections above with the phase's specific screen states, since this is a 3-screen interactive flow — sourced entirely from CONTEXT.md decisions D-01 through D-11, no open questions remain.)

### Setup Screen
- Tense multi-select: 4 chips (one per tense, label via `tenseLabels`) + 1 "All tenses" shortcut chip. Selected state = accent-filled (`#007AFF` background, white text). Unselected = secondary background (`#F2F2F7`), black text. "All tenses" shows selected state only when all 4 individual tenses are selected (derived, not independently tracked — per RESEARCH.md Pattern 3).
- Irregular toggle: RN `Switch`, off by default (SETUP-02), label "Include irregular verbs" to its left, no helper text.
- "Start Quiz" button: accent-filled, full-width or centered, disabled (opacity ~0.4, non-interactive) when 0 tenses selected.
- Error state: red-tinted or plain-label inline text (Label size, `#FF3B30` or default black — implementer's choice since D-04 doesn't specify color, but must be visually distinct from normal copy) appears only after a failed "Start Quiz" attempt; clears automatically on next successful filter change/attempt.

### Quiz Screen
- Top: progress counter (Label size, e.g. "3 / 10") + horizontal progress bar (accent-filled portion over secondary-background track).
- Question block: infinitive verb (Heading size), English translation + tense label + subject pronoun label (Body/Label size) — all four required per QUIZ-01.
- 4 answer choices: stacked vertically, secondary background by default, Body size text, minimum 44pt touch height.
- On tap (D-05/D-06): tapped choice becomes green if correct, red if wrong; if wrong, the actual correct choice is simultaneously highlighted green. All 4 choices become non-interactive (no opacity change needed beyond the color feedback, but visually inert — no press states) immediately after the first tap.
- "Next" button (accent-filled) appears/becomes enabled only after a choice is locked — never before, no auto-advance timer (D-07).

### Results Screen
- Score "X/10" rendered at Display size (56px/600), vertically centered as the visual anchor of the screen (D-09).
- Three actions below the score, in this order: "Share Score" (opens native share sheet, D-10 exact message), "Try Again" (accent-filled, primary emphasis — re-derives session via same filters, D-11), "Back to Setup" (secondary/outline emphasis, lower visual weight than "Try Again").
