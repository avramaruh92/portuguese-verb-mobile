  <behavior>
    - Test 1: `shuffle([1,2,3,4,5], mockRandom([...]))` with a fixed RNG sequence returns an exact, asserted permutation (deterministic output for a known sequence).
    - Test 2: shuffle returns a NEW array; the input array is unmutated after the call.
    - Test 3: shuffle output is a permutation — same length and same multiset of elements as the input (sorting both and comparing yields equal arrays).
    - Test 4: `shuffle([], random)` returns `[]` and `shuffle([x], random)` returns `[x]` (edge cases, zero/one element).
  </behavior>
  <action>
    Create src/quiz/random.ts exporting
    `function shuffle<T>(items: readonly T[], random: () => number): T[]` implementing the
    Durstenfeld Fisher-Yates variant: copy the input with spread, iterate i from length-1 down
    to 1, compute `j = Math.floor(random() * (i + 1))`, swap result[i] and result[j]. Use
    non-null assertions (`!`) at the swap site with a short comment noting i and j are always
    valid indices by the loop invariant (required by noUncheckedIndexedAccess). CRITICAL:
    `random` has NO default value here (only the top-level generate() in Wave 2 defaults to
    Math.random) so a missed thread-through in a caller is a compile error, per RESEARCH Pitfall 1.
    Create __tests__/quiz-random.test.ts with an inline `mockRandom(sequence: number[])` helper
    (returns a closure yielding sequence values, cycling via `sequence[i++ % sequence.length]!`)
    and the four behaviors above, mirroring dataset.test.ts conventions.
  </action>

    <automated>npx jest __tests__/quiz-random.test.ts && npm run typecheck</automated>
  </verify>
