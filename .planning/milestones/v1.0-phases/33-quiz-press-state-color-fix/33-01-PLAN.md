<objective>
Fix the quiz answer-choice press-state color bug: pressing-and-holding an
unsubmitted choice currently paints it `colors.pressed` (`#C94A2D`), a dark
red close enough to `colors.error` (`#D64545`) that a learner reads it as
"wrong answer" before submitting. Add a dedicated neutral
`colors.choicePressed` token, extract the split locked-state/pressed-state
logic in `app/quiz.tsx` into one pure function under `src/quiz/`, and prove
via unit tests that locked correct/incorrect coloring always beats the
pressed color.

Purpose: press feedback must read as "tap acknowledged," never as a
correctness signal (UX-01, UX-02, UX-03).
Output: `colors.choicePressed` token, `src/quiz/choiceStyle.ts`,
`__tests__/quiz-choice-style.test.ts`, rewired `app/quiz.tsx`.
</objective>
