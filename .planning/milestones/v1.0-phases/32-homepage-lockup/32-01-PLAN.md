<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo SVG source → build-time renderer | `assets/brand/lafa-homepage-lockup.svg` is parsed by `linkedom` and rendered by `@resvg/resvg-js` inside the developer's build step. The input is version-controlled repo content, not user- or network-supplied. |
| build output → app bundle | The generated PNG is committed and later bundled by Metro. No runtime code executes from it. |

This phase's attack surface is minimal and stated explicitly: a local, build-time asset pipeline plus a static image render. There is no user input, no network call, no authentication, no persistence, and no new dependency install (the phase uses `linkedom`, `@resvg/resvg-js`, and `sharp`, all already-audited Phase 31 devDependencies).

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-01 | Tampering | `assets/brand/lafa-homepage-lockup.svg` mark slot | mitigate | `buildLockupDoc()` throws a descriptive error when the slot id is missing, the slot has no element children, or the post-injection serialization lacks the three mark layer ids — a tampered/malformed source fails the build instead of shipping a silently wrong brand asset. |
| T-32-02 | Tampering | Rendered PNG dimensions | mitigate | Explicit `lockupRender.width/height !== LOCKUP_WIDTH_PX/LOCKUP_HEIGHT_PX` guard, mirroring the existing icon-render guard, so a viewBox/fitTo change cannot ship an off-size asset. |
| T-32-03 | Tampering | Existing five generated brand PNGs | mitigate | Acceptance criterion requires `git status --porcelain assets/images` to list only the new PNG, catching any regression the new step leaks into shared code paths. |
| T-32-04 | Information disclosure | Generated PNG contents | accept | The lockup contains only public brand artwork (mark, wordmark, tagline). No secrets, PII, or environment data enter the render path. |
| T-32-05 | Denial of service | `Resvg` render of a repo-controlled SVG | accept | Build-time only, developer-triggered, no untrusted input; a malformed source fails fast rather than hanging. |
| T-32-SC | Tampering | npm installs | accept | This plan installs no packages — `linkedom`, `@resvg/resvg-js`, and `sharp` are already-present devDependencies cleared by Phase 31's legitimacy gate (T-31-SC). No new supply-chain surface is introduced, so no install checkpoint is required. |
</threat_model>
