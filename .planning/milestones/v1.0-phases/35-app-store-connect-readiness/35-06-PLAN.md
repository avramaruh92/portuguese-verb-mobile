<objective>
Produce and deliver the binary that Apple will review (STORE-08), and close the deferred half of
BRAND-04 by confirming the icon is alpha-free on the real production build rather than only on the
source PNG.

Purpose: the listing cannot be submitted for review without a build attached in App Store Connect.
`eas.json`'s production profile already has `autoIncrement: true` with
`cli.appVersionSource: "remote"`, so the build number bump is automatic — this plan's job is to run
the pipeline against the final source, prove the gates were green first, and capture evidence.

Output: an EAS production build delivered to App Store Connect, with its build id, build number,
and icon-alpha evidence recorded.

**Interactive:** `eas build` and `eas submit` are long-running cloud operations, and `eas submit`
uses interactive Apple ID authentication (this project has no App Store Connect API key configured
in `eas.json`, only `ascAppId` — that is expected and sufficient per research; a 2FA prompt is
normal, not a failure).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local source tree -> EAS cloud build | Whatever is on disk becomes the reviewed binary; uncommitted or unreviewed changes would ship silently |
| developer machine -> Apple ID authentication | Interactive credentials/2FA cross into Apple's systems during `eas submit` |
| build artifact -> App Store Connect | Once uploaded, a build number is permanently consumed and cannot be reused |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-19 | Tampering | Building from a dirty or unreviewed working tree, shipping unintended code | mitigate | Task 1 asserts `git status --porcelain` is clean for `src/`, `app/`, `assets/`, `app.json`, `eas.json`, and Task 2 records the source commit of the build |
| T-35-20 | Spoofing | Apple ID credentials entered into a non-Apple prompt | mitigate | Only the official `eas submit` interactive flow is used; the plan forbids adding API key files to the repo and forbids `npx eas-cli@latest` in favour of the pinned global `eas-cli` 21.2.0 |
| T-35-21 | Information Disclosure | Committing an App Store Connect API key (`.p8`) or Apple credentials into the repo | mitigate | Task 3 explicitly forbids adding `ascApiKeyPath`/`ascApiKeyIssuerId`/`ascApiKeyId` to `eas.json`; acceptance asserts their continued absence |
| T-35-22 | Denial of Service | Duplicate or non-incremented build number rejected by Apple, blocking submission | mitigate | Task 1 records the baseline build number and Task 2 asserts the new build number is strictly greater |
| T-35-23 | Tampering | Icon regression reaching users because alpha was only ever checked on the source PNG | mitigate | Task 2 checks `hasAlpha` on `AppIcon*.png` inside the real `.ipa`, with a delete-and-reinstall visual fallback when icons are compiled into `Assets.car` |
| T-35-SC | Tampering | npm/pip/cargo installs | mitigate | Not applicable — no packages installed; `eas-cli` 21.2.0 is already globally installed and the plan forbids `npx eas-cli@latest` or reintroducing a local devDependency |
</threat_model>
