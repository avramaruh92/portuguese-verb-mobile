<objective>
Produce the auditable source of truth for the App Privacy nutrition label (STORE-03): a per-call
data-flow table mapping each of the app's three network requests to the exact Apple data type,
purpose, and linkage answer that plan 35-07 will enter in App Store Connect — and confirm on the

request logger emitted `remoteAddress: req.ip` on every request; plan 35-01 fixed that (D-13,
Option A). This plan records the resulting classification with evidence and verifies the fix in
production, so the answers entered in Apple's questionnaire are unconditional.

plan summary.

<!-- Verified data-flow facts. RESEARCH.md §"Backend Data-Retention Investigation" is the source. -->

| Call | Fields sent by the client | Backend persists | Backend logs |
|------|---------------------------|------------------|--------------|
| `POST /feedback` | message, verb, tense, subject, correctAnswer, selectedAnswer, appVersion, platform | the same fields plus generated `id`, `createdAt` — no IP, no user agent, no device id column exists in `FeedbackReport` | curated `req.log.info({id, verb, tense, subject, platform, appVersion, outcome})` — no client identifiers |
| `POST /product-feedback` | category, message, screen, appVersion, platform | the same fields plus `id`, `createdAt` in `ProductFeedbackReport` — no IP/UA/device columns | curated `req.log.info(...)` — no client identifiers |
| `GET /content/verbs` | nothing — no body, no auth header, no identifiers | nothing (read-only) | nothing beyond the framework line that 35-01 disabled |

Pre-fix behavior: `Fastify({ logger: true })` with no `disableRequestLogging` override caused
Fastify's built-in request logger to emit an "incoming request" line per request, whose default
`req` serializer (`fastify/lib/logger-pino.js`) returns `remoteAddress: req.ip`. Those lines went
only to Render's rolling platform log stream — never to the app's database, never to any third
party (no Sentry/Datadog/Logtail/analytics SDK exists in the backend; `render.yaml` configures no
log-streaming add-on).
Post-fix (plan 35-01): `Fastify({ logger: true, disableRequestLogging: true })` — the automatic
request lines are suppressed; the curated per-route lines still emit.

Locked user decisions: D-07 (feedback message content -> "Data Not Linked to You", category
"User Content"), D-08 (`GET /content/verbs` -> "Data Not Collected"), D-13 (Option A backend fix
is in scope and was executed in plan 35-01).

The app contains no analytics, advertising, attribution, or crash-reporting SDK, no advertising
identifier, no device identifier collection, and does no cross-app/website tracking.
