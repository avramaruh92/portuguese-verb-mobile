## Directory Purposes

**`app/`:**
- Purpose: Expo Router route definitions — one file per screen, file path = URL path
- Contains: React components only, each with its own colocated `StyleSheet.create` block; no business logic beyond thin event handlers that call into `src/store/useQuizStore.ts`
- Key files: `app/_layout.tsx` (root shell, prefetch trigger), `app/index.tsx`, `app/quiz.tsx`, `app/results.tsx`

**`src/dataset/`:**
- Purpose: Owns the verb data — its shape, its two possible sources (remote/local), and runtime shape validation
- Contains: Types, a large data literal (`verbs.ts`), fetch logic, and a Zod schema
- Key files: `src/dataset/source.ts` is the only file other layers should import from for *resolving* verbs at runtime (`resolveVerbs`/`prefetch`); `src/dataset/verbs.ts` is imported directly only by `src/quiz/engine.ts` (as its default parameter) and `app/quiz.tsx` (to look up the current verb's translation)

**`src/quiz/`:**
- Purpose: Pure quiz-generation and scoring logic, no React/RN imports anywhere in this directory
- Contains: Question generation (`engine.ts`), randomness (`random.ts`), scoring (`scoring.ts`), share text (`share.ts`), UI label lookup tables (`labels.ts`), shared types (`types.ts`)
- Key files: `src/quiz/engine.ts` is the entry point the store calls; everything else in this directory is either a helper it uses or a display/formatting utility screens import directly

**`src/feedback/`:**
- Purpose: End-to-end "report a problem" flow — UI, payload shaping, contract schema, and submission
- Contains: One RN component (`ReportFeedbackModal.tsx`) plus pure modules for payload building, reason labels, Zod schema, and the fetch wrapper
- Key files: `src/feedback/submit.ts` is the only file that talks to the network; `src/feedback/schema.ts` is the single source of truth for the backend contract shape (enums reuse `dataset/types.ts`'s `TENSES`/`SUBJECTS`)

**`src/store/`:**
- Purpose: The single cross-screen state container
- Contains: One file, one Zustand store
- Key files: `src/store/useQuizStore.ts`

**`src/components/`:**
- Purpose: Small reusable presentational components shared across screens (currently just one)
- Contains: `OfflinePill.tsx`
- Key files: `src/components/OfflinePill.tsx`

**`src/theme/`:**
- Purpose: Design tokens (colors, spacing, radius, typography) as flat const exports — no ThemeProvider/context
- Contains: `tokens.ts` and its co-located test `tokens.test.ts`
- Key files: `src/theme/tokens.ts`

**`__tests__/`:**
- Purpose: Jest test suite for everything except `src/theme/tokens.ts` (which is co-located instead)
- Contains: One test file per source module, flat naming with directory prefix (e.g. `dataset-remote.test.ts` tests `src/dataset/remote.ts`), plus `smoke.test.ts`
- Key files: `__tests__/useQuizStore.test.ts` (store), `__tests__/quiz-engine.test.ts` (question generation)

**`assets/`:**
- Purpose: Static app icons and splash images referenced from `app.json`
- Generated: `assets/expo.icon/` is managed by Expo's icon tooling
- Committed: Yes

**`ios/`:**
- Purpose: Native iOS Xcode project, generated by Expo prebuild/EAS for local native builds
- Generated: Yes (regenerable via `expo prebuild`)
- Committed: Check `.gitignore` before assuming — typically excluded from source control in managed Expo workflows; do not hand-edit files here expecting them to persist across a prebuild

## Key File Locations

**Entry Points:**
- `app/_layout.tsx`: Root layout, mounted once at launch, triggers dataset prefetch
- `app/index.tsx`: Default route (`/`), quiz setup

**Configuration:**
- `app.json`: Expo app config (name, icon, plugins, splash)
- `tsconfig.json`: `expo/tsconfig.base` + `strict: true` + `noUncheckedIndexedAccess: true`
- `package.json`: Scripts (`start`, `android`, `ios`, `web`, `lint`, `test`, `typecheck`) and the Jest preset (`jest-expo`) configured inline under `"jest"`

**Core Logic:**
- `src/store/useQuizStore.ts`: Cross-screen state and orchestration
- `src/quiz/engine.ts`: Question generation
- `src/dataset/source.ts`: Content resolution (remote/local)
- `src/feedback/submit.ts`: Feedback network call

**Testing:**
- `__tests__/*.test.ts`: Jest suite (run via `npm test`)
- `src/theme/tokens.test.ts`: The one co-located test file

## Naming Conventions

**Files:**
- Screens: lowercase route name matching the URL segment (`index.tsx`, `quiz.tsx`, `results.tsx`), plus the reserved `_layout.tsx`
- Source modules: lowercase, singular-purpose (`engine.ts`, `scoring.ts`, `submit.ts`, `payload.ts`) — one exported concern per file
- Components: PascalCase matching the exported component (`OfflinePill.tsx`, `ReportFeedbackModal.tsx`)
- Tests: `__tests__/<area>-<module>.test.ts` (e.g. `dataset-remote.test.ts`, `feedback-submit.test.ts`, `quiz-engine.test.ts`) — the directory prefix from `src/` is flattened into the filename; the one exception is `src/theme/tokens.test.ts`, co-located next to `tokens.ts`

**Directories:**
- `src/` subdirectories are named after the domain concern they own (`dataset`, `quiz`, `feedback`, `store`, `components`, `theme`), each containing a `types.ts` if it needs shared local types

## Where to Add New Code

**New Screen/Route:**
- Add a new file directly under `app/` — Expo Router derives the route from the filename (e.g. `app/settings.tsx` → `/settings`)
- Import shared state from `src/store/useQuizStore.ts` and shared tokens from `src/theme/tokens.ts`, following the pattern in `app/results.tsx`

**New Quiz Logic (e.g. new question type, new scoring rule):**
- Add a pure function to the relevant file in `src/quiz/` (or a new file if it's a distinct concern), keep it framework-free (no React/RN imports) so it stays unit-testable
- Add a corresponding test in `__tests__/quiz-<name>.test.ts`

**New Dataset Field/Source:**
- Extend `src/dataset/types.ts` for the type, `src/dataset/validate.ts` for the Zod schema, `src/dataset/verbs.ts` for local data — keep `resolveVerbs()` in `src/dataset/source.ts` as the single resolution entry point other layers call

**New Feedback Field/Endpoint:**
- Update `src/feedback/schema.ts` first (single source of truth for the contract), then `src/feedback/types.ts`/`payload.ts`/`submit.ts` follow from the schema's inferred type — cross-check against the backend repo's Zod contract before changing enum literals (see `CLAUDE.md`'s cross-repo contract risk note)

**New Shared Component:**
- Add to `src/components/`, import `colors/spacing/radius/typography` from `src/theme/tokens.ts` rather than hardcoding style values (see `ARCHITECTURE.md` Anti-Patterns for the one file — `ReportFeedbackModal.tsx` — that currently doesn't follow this)

**Utilities:**
- No generic `src/utils/` directory exists; small helpers live directly in the domain directory that uses them (e.g. `src/quiz/random.ts`, `src/quiz/labels.ts`). Follow this pattern rather than introducing a catch-all utils folder.
