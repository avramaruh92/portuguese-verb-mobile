## Directory Purposes

**`app/`:**
- Purpose: Expo Router route files. Each file maps to a URL route. Nothing else lives here.
- Contains: 4 `.tsx` files. Only the route components and their `StyleSheet` blocks.
- Key files: `app/_layout.tsx` (root), `app/index.tsx`, `app/quiz.tsx`, `app/results.tsx`.
- Adding a route: create `app/<name>.tsx` with a default export. Expo Router registers it automatically. `experiments.typedRoutes` is enabled in `app.json`, so `.expo/types/router.d.ts` is regenerated.

**`src/config/`:**
- Purpose: Environment-level constants.
- Contains: `api.ts` only. `API_BASE_URL = "https://portuguese-verb-api-fra.onrender.com"` (Frankfurt).
- Key files: `src/config/api.ts`
- Rule: every app-side endpoint derives from `API_BASE_URL`. `__tests__/api-host-guard.test.ts` fails if the retired Oregon host appears in the source tree. `scripts/preflight.ts` keeps its own literal because Node type-stripping cannot import from `src/`.

**`src/dataset/`:**
- Purpose: Verb content: types, bundled data, remote fetch, validation, source resolution.
- Contains: `types.ts` (Tense, Subject, Verb, TENSES, SUBJECTS), `verbs.ts` (1954 lines, 50 verbs, local fallback), `remote.ts` (`GET /content/verbs`), `validate.ts` (Zod), `source.ts` (`prefetch`, `resolveVerbs`, cache, background retry).
- Key files: `src/dataset/source.ts`, `src/dataset/verbs.ts`, `src/dataset/types.ts`

**`src/learning/`:**
- Purpose: Wrong-answer explanations from remote-served templates.
- Contains: `schema.ts` (LearningContentSchema, FormMatchSchema), `types.ts`, `explain.ts` (`selectExplanation`).
- Key files: `src/learning/explain.ts`

**`src/quiz/`:**
- Purpose: Pure quiz logic. No React, no RN.
- Contains: `engine.ts` (generate, sampleTriples, buildQuestion, pickDistractors), `random.ts` (shuffle), `scoring.ts` (score), `labels.ts` (subject and tense labels), `choiceStyle.ts` (per-choice visual variant), `share.ts` (buildShareMessage), `types.ts` (Triple, Question, QuizSession, GenerateOptions, VerbMode, InsufficientVerbsError).
- Key files: `src/quiz/engine.ts`, `src/quiz/types.ts`

**`src/store/`:**
- Purpose: The one Zustand store.
- Contains: `useQuizStore.ts` only.
- Key files: `src/store/useQuizStore.ts`

**`src/feedback/`:**
- Purpose: Report-a-problem flow for a quiz question.
- Contains: `ReportFeedbackModal.tsx` (UI), `payload.ts` (builds payload, prefixes reason label to message), `schema.ts` (Zod, `feedbackPayloadSchema`), `submit.ts` (`POST /feedback`), `reasons.ts` (`FEEDBACK_REASONS`, `reasonLabels`), `types.ts`.
- Key files: `src/feedback/ReportFeedbackModal.tsx`, `src/feedback/submit.ts`

**`src/productFeedback/`:**
- Purpose: General product feedback from any screen.
- Contains: `ProductFeedbackModal.tsx` (UI), `payload.ts`, `schema.ts`, `submit.ts` (`POST /product-feedback`), `categories.ts` (`CATEGORY_OPTIONS`, `categoryLabels`), `types.ts` (`SCREENS`, `ProductFeedbackCategory`).
- Key files: `src/productFeedback/ProductFeedbackModal.tsx`, `src/productFeedback/submit.ts`

**`src/components/`:**
- Purpose: Cross-domain presentational components.
- Contains: `OfflinePill.tsx` (exports `OfflinePill`, `isLocalSource`, `OFFLINE_PILL_TEXT`), `ExplanationPanel.tsx`.
- Key files: `src/components/OfflinePill.tsx`

**`src/theme/`:**
- Purpose: Design tokens and the homepage lockup crop constants.
- Contains: `tokens.ts` (`colors`, `spacing`, `radius`, `typography`), `lockup.ts` (`LOCKUP_CONTENT_X0/Y0/X1/Y1`, import-free so Node scripts can load it), `tokens.test.ts` (co-located test).
- Key files: `src/theme/tokens.ts`

**`__tests__/`:**
- Purpose: Jest unit tests. One file per module, named `<domain>-<module>.test.ts`. Mostly plain function tests with no component rendering.
- Contains: 22 `*.test.ts` files plus `fixtures/content-verbs-v0.4.sample.json`.
- Key files: `__tests__/quiz-engine.test.ts`, `__tests__/useQuizStore.test.ts`, `__tests__/dataset-source.test.ts`, `__tests__/api-host-guard.test.ts`, `__tests__/contract-fixture.test.ts`

**`scripts/`:**
- Purpose: Node tooling, run through `npm run <script>`. Not part of the app bundle.
- Contains: `generate-brand-assets.ts` (`generate-assets`, uses `@resvg/resvg-js`), `validate-brand.ts` (`validate-brand`, uses `sharp`), `preflight.ts` (`preflight`, probes `/health`, `/content/verbs`, `/feedback`, `/product-feedback`), `brand-colors.ts` (shared color constants for the asset scripts).
- Note: `scripts/brand-colors.ts` and `scripts/validate-brand.ts` depend on `src/theme/lockup.ts` staying import-free.

**`store/`:**
- Purpose: App Store Connect submission material. This is unrelated to the Zustand store under `src/store/`.
- Contains: metadata text, privacy answers, screenshots, and `submission-log.md`.

**`assets/`:**
- Purpose: Source brand assets and rendered images referenced from `app.json`.
- Contains: `brand/` (SVG source files and `candidates/`), `images/` (PNG outputs).

**`docs/`:**
- Purpose: Static HTML for the public site (landing, privacy, support). Not compiled by Expo.

**`ios/`:**
- Purpose: Native project generated by Expo prebuild. Git-ignored. Do not hand-edit.

## Naming Conventions

**Files:**
- Route files: lowercase, matching the URL segment (`index.tsx`, `quiz.tsx`, `results.tsx`). `_layout.tsx` is reserved by Expo Router.
- Components: `PascalCase.tsx` (`OfflinePill.tsx`, `ReportFeedbackModal.tsx`, `ProductFeedbackModal.tsx`, `ExplanationPanel.tsx`).
- Logic modules: lowercase single word (`engine.ts`, `random.ts`, `scoring.ts`, `labels.ts`, `choiceStyle.ts`, `payload.ts`, `submit.ts`, `schema.ts`, `types.ts`, `reasons.ts`, `categories.ts`, `source.ts`, `remote.ts`, `validate.ts`, `explain.ts`). Only `productFeedback/` uses a camelCase folder name.
- Store: `useXStore.ts` (`useQuizStore.ts`).
- Tests: `__tests__/<domain>-<module>.test.ts` (e.g. `dataset-remote.test.ts`, `productFeedback-submit.test.ts`). The `productFeedback-` prefix keeps camelCase. The exception is `src/theme/tokens.test.ts`, co-located.
- Scripts: lowercase kebab-case (`generate-brand-assets.ts`, `validate-brand.ts`).

**Directories:**
- Under `src/`: lowercase single word (`dataset`, `quiz`, `store`, `theme`, `config`, `components`, `learning`, `feedback`), with the exception of `productFeedback` (camelCase).
- Under `app/`: flat. Expo Router route segments only.

**Identifiers:**
- Types and components: `PascalCase`. Functions: `camelCase`. Constants: `SCREAMING_SNAKE_CASE` (`API_BASE_URL`, `TIMEOUT_MS`, `QUESTIONS_PER_SESSION`, `OFFLINE_PILL_TEXT`).
- Tense and subject keys use snake_case as data keys: `present_indicative`, `ele_ela`, `eles_elas`.

## Where to Add New Code

**New quiz rule or scoring change:**
- Primary code: `src/quiz/engine.ts` (generation) or `src/quiz/scoring.ts` (scoring)
- Types: `src/quiz/types.ts`
- Tests: `__tests__/quiz-engine.test.ts` or a new `__tests__/quiz-<module>.test.ts`

**New screen:**
- Route file: `app/<name>.tsx`, with a `Stack.Screen` override inside it if needed
- Screen-specific logic: keep it in the route file only if it is pure UI. Logic goes in `src/<domain>/`.

**New store state or action:**
- Implementation: `src/store/useQuizStore.ts` (add to `QuizStoreState` and `initialState`). Keep `reset()` consistent with `initialState`.
- Tests: `__tests__/useQuizStore.test.ts`

**New dataset field or content source:**
- Types: `src/dataset/types.ts`
- Validation: `src/dataset/validate.ts` (verbs) or `src/learning/schema.ts` (learning)
- Remote parse: `src/dataset/remote.ts`
- Resolution: `src/dataset/source.ts`
- Local fallback data: `src/dataset/verbs.ts`

**New backend endpoint:**
- Constant: derive from `API_BASE_URL` in `src/config/api.ts`. Do not hardcode a host. Add the path in the owning module, e.g. `` `${API_BASE_URL}/<path>` ``.
- Module: follow the `submit.ts` pattern in `src/feedback/` or `src/productFeedback/` (AbortController, 45s or 15s timeout, tagged `SubmitResult`).
- Add the endpoint to `scripts/preflight.ts` if it should be probed.
- Contract: check the sibling backend repo before wiring a new payload. The backend's Zod enums for `tense`, `subject`, and `platform` must match `src/dataset/types.ts`.

**New shared component:**
- Implementation: `src/components/<PascalCase>.tsx`, named export.

**New design token:**
- `src/theme/tokens.ts`. Use the tokens in components. Do not inline hex colors or spacing values.

**New feedback-type surface:**
- Copy the structure of `src/productFeedback/` (`types`, `schema`, `payload`, `submit`, modal) rather than adding to one of the existing folders.

**Utilities:**
- Pure helpers belong in the owning domain folder (`src/quiz/random.ts` for shuffle). There is no shared `src/utils/`.

**Tests:**
- Add `__tests__/<domain>-<module>.test.ts` for each new `src/` module. Keep logic framework-free so it runs without rendering.
