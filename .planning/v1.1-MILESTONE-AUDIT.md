## Integration (gsd-integration-checker)

**22/22 requirements wired, 4/4 flows, 0 blockers.** The checker ran Jest
(23 suites, 277 tests), typecheck (clean) and `validate-brand` (40/40).

- **Base URL.** `API_BASE_URL` in `src/config/api.ts` points at Frankfurt.
  The three live clients use it: `src/dataset/remote.ts`,
  `src/feedback/submit.ts` and `src/productFeedback/submit.ts`. These are
  the only `fetch(` call sites in `src/`, `app/` and `scripts/`, apart from
  preflight.
- **Preflight.** `scripts/preflight.ts` keeps its own Frankfurt literal by
  design, and the Oregon guard test covers it.
- **Timeouts.** Content is 15s and both feedback POSTs are 45s. Preflight
  budgets match. The content fetch sends `{ signal }` only, and any non-OK
  response falls back to the bundled dataset.
- **Phase 39 changes.** `app/index.tsx` imports `../src/theme/lockup`
  without a `.ts` suffix, and `lockup.ts` has no imports. Suffixed imports
  appear only in `scripts/validate-brand.ts`, which runs under Node type
  stripping. Nothing in Phases 36–38 depends on the moved code.

| Flow | Status |
|---|---|
| App start → `prefetch()` → Frankfurt `/content/verbs` (15s) → quiz → results | WIRED |
| Fetch failure / offline → local dataset → `OfflinePill` | WIRED (E2E-04 device evidence in Phase 37) |
| Report a problem / product feedback → POST (45s) → 201 / error union | WIRED (201s on device in Phase 37) |
| Release → HAND-01/HAND-02 → backend Oregon deletion (2026-10-14) | WIRED |

The checker did not re-run the real-device E2E or `npm run preflight`. Its
checks of the release and E2E evidence are cross-checks of the documents.
