## Gap: UI-03 (Partial)

**The requirement as written cannot be exercised.** UI-03 calls for "styled loading and error states" for "the new online-fetch step." The loading half is real and reachable (`ActivityIndicator` while `startQuiz()` awaits `resolveVerbs()`). The error half exists as styled UI but has **no live trigger**: Phase 7's `resolveVerbs()` was deliberately built (per FETCH-03, and locked by a passing test) to *never* surface a fetch failure to the caller — it silently falls back to the bundled dataset every time. The only path that currently sets `status: "error"` in the store is `InsufficientVerbsError`, a filter/dataset-size condition that has nothing to do with the network.

This is not a bug in either phase — Phase 7 did exactly what FETCH-03 asked, and Phase 10 built a real, correctly-styled error UI. The gap is a **requirements-level contract tension** between FETCH-03 and UI-03 that surfaces only when checked cross-phase (which is exactly what this audit step is for).

**Options to close:**
1. **Re-scope UI-03** to explicitly mean "the insufficient-verbs error state on the fetch/start step" (already satisfied as-is) and drop the fetch-failure framing — lowest-effort, matches what was actually built.
2. **Add an intentional, narrow carve-out to FETCH-03's silence** — e.g., surface `source === "local"` as a small non-blocking banner/toast ("Showing offline content") distinct from a blocking error — gives UI-03 a real, low-severity trigger without violating FETCH-03's "no user-facing blocking" clause.
3. **Accept as known tech debt** and proceed — the loading state (the more user-visible half of UI-03) works correctly; the error half is inert but harmless code, not a broken experience.
